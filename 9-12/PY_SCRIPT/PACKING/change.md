# 需求变更记录

## 2026-09-18：PDF 批量生成装箱单

本次记录基于当前代码相对上一提交的变更，作为本次提交的需求与验收依据。

### 1. 直接处理目录中的全部 PDF

- 主流程调整为选择订单 PDF 目录、JP 产品资料表、订单排期表和输出目录后，点击“直接处理所有pdf订单”生成装箱单，无需先识别图片。
- 递归扫描子目录，显示 PDF 相对路径及总数；点击处理时重新扫描，逐份处理。
- 从 PDF 正文的 `PURCHASE ORDER NO.` 提取唯一的 `POHK-数字-数字-数字` 订单号，不依赖 PDF 文件名。
- 单份 PDF 无法解析或订单号不唯一时记录失败并继续后续文件；结束后汇总成功、跳过和失败数量。
- 保留目标文件存在即跳过、不覆盖既有装箱单，以及生成成功后请求 Excel 打开的行为。

验收：任意文件名的 PDF 可按正文订单号处理；子目录及大写 `.PDF` 文件可被扫描；坏文件不阻断后续处理；空目录正常结束。

### 2. 忽略数量为零的订单明细

- PDF 中 `QTY = 0 PCS`（含小数形式）的 ITEM 直接忽略，不要求其装箱量、客户 PO、日期或产品资料完整。
- 非零明细仍执行装箱量和整除等校验；缺少 QTY 仍报错。
- 全部 ITEM 数量为零的订单计入跳过，不查询产品资料、不生成空装箱单。

验收：零数量明细不影响同一订单的有效明细；全零订单无输出文件；非零明细的无效装箱量仍被拒绝。

### 3. 输出命名与 slip sheet 格式

- 输出文件统一命名为 `<订单号>_packing_list.xlsx`，保存到所选输出目录，重名检查使用同一命名规则。
- 装箱单备注中的 `slip sheet` 使用红色加粗富文本，其余备注文字保持原有格式；匹配不区分大小写。

验收：已有同名文件保持不变；生成的 Excel 中 `slip sheet` 文本为红色、加粗，前后文字完整。

### 4. PDF 工作流界面与选择弹窗

- 主界面显示 PDF 列表和批量处理按钮，隐藏图片选择、重新识别、识别结果导出及旧生成入口，保留相关代码。
- 启动时恢复 PDF 和输出目录，不再恢复图片并自动执行 OCR；OCR 服务改为调用识别时才加载。
- 扩大日志区域、缩小列表区域，显示扫描中、空目录和扫描失败等状态。
- 装箱资料选择弹窗按候选数量和内容调整尺寸，并限制在屏幕可用范围内；选择候选后重新适配窗口。

验收：仅使用 PDF 流程即可发起生成；处理期间相关操作禁用，结束后恢复；弹窗尺寸适配仍需实际桌面环境目视确认。
