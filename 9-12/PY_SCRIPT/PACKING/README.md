# 自动装箱生成系统

## 入仓预申报ASN生成器（默认首页）

点击“选择三文件所在的目录”，选择包含 `形式发票<合同号>.xls`、`装箱单<合同号>.xls`、`香港合同<合同号>.xls` 的目录（同时支持 `.xlsx` 和“销售合同”前缀）。只扫描当前目录；有多组合同则分别检查。缺文件、同类重复文件、文件损坏都会报错，不会任意选择一份。

- 打开每份单据首先核对表内合同号与文件名。详细日志记录文件名、工作表、单元格、品名、规格、商品编码、数量、箱数、消费国、单价、金额、净毛重及合同签订日期，保存在程序目录 `logs/asn-YYYY-MM-DD.log`。每天一个 UTF-8 文件，同日重复核对或重启后继续追加，跨天自动换文件，每次核对带独立标记。
- 检查三单品名、总数量、逐品名及单价汇总的数量/金额、三单总金额，以及单据内部“数量 × 单价”、明细合计、装箱数量及箱数合计。金额按美分四舍五入核对，数量与单价精确比较。
- 适配提供样本的多层表头：装箱单“每箱数量”下实际是单价和总价列，每箱数量以“总数量 ÷ 箱数”推算并明确标注；不能整除时提示异常，混装需人工确认。
- 界面“核对结果”只显示每个合同的通过结论和需要处理的异常，不展示逐行过程、单元格位置、时间戳与日志级别。一致与异常分别用绿色、红色粗体显示，下方注明详细日志文件路径；日志保存失败会提醒，但继续核对。空值、未缓存的 Excel 公式、无法识别的表头不会被视为核对成功；请用 Excel 重新计算保存后重试。
- “选择输出目录”显示并记住 ASN 保存位置，写入 `settings.json` 的 `asn_output_directory`，重启自动恢复。三单核对通过并读取海关装箱单后，点击“生成 ASN”直接保存到该目录；未选择或目录失效时提示重新选择，取消保留原选择。生成文件名为 `ZLC盐田综合保税区仓库 -入仓预申报ASN表格-<合同号>.xls`。保留 sample 中的全部工作表及原顺序，只填写“报关资料与ASN”页；其他页保留内容、公式和格式（关联公式随 ASN 重新计算，原有失效公式不修改），保留模板格式，按 PL 原顺序一行对应一行，不合并。需要 Windows 本机安装 Microsoft Excel，使用后台独立实例保存真正的 `.xls`；不修改源文件，同名文件不覆盖。
- 境外收货人（C8）取所选海关装箱单的 Customer；Customer 为空或多行客户不一致时提示核实，不猜填。其余公司资料、联系人及海关/贸易方式沿用样本；合同号和签订日期来自核对后的合同；申报日期为生成当天。计价数量及单位逐商品取形式发票；法1/法2单位按 HS 编码联网查询，千克数量取 PL 总净重；P/O# 取 PL 的 CUSTOMER ORDER NO；原产国“中国”；以星仓货源地“达州市”、产地代码“51169”（星辉仓按其模板填写）；车牌留空，司机信息不生成。
- 日期按 Excel 日期数值写入，优先保留模板日期显示格式，原格没有日期格式时使用 `yyyy-mm-dd`；总箱数和产地代码按数字写入，恢复附表中的产地代码匹配。PO、SKU、合同号等编号仍按文本保存，保留前导零。固定公司资料不重写，保留原有类型与格式。
- 保留模板已有各行的字体、边框、对齐、数字格式及行高，仅超过模板现有范围的新行复制明细格式；保持原打印区域，新增行超出已设打印区域时才扩展。中通及星辉模板的各页打印缩放在 Excel 保存后按源模板还原，避免自动适配导致缩放值变化。
- 生成前单选“以星仓 ASN / 中通仓 ASN / 星辉仓 ASN”，`settings.json` 的 `asn_warehouse` 记住选择；处理中锁定切换。以星仓使用原 `.xls` 模板（14 页）；中通仓使用 `templates/asn_zhongtong_template.xlsx`（18 页，含隐藏页），只填写其中的 `ASN` 页。中通输出名为 `中通仓-入仓预申报ASN表格-<合同号>.xlsx`，SKU 取 PL 的 Customer Item No.，交仓日期与备注留空，发票号使用合同号，总箱数按 PL 汇总。三种格式均保留模板附表、公式、字体和页顺序，同一份 PL 一行对应一行。
- 星辉仓使用 `templates/asn_xinghui_template.xlsm`，输出 `星辉仓-入仓预申报ASN表格-<合同号>.xlsm`，保留全部 17 页、原始 VBA 项目、工作表保护及右侧下拉参考数据。只填写“报关资料与ASN”页，最多 971 条明细；生成时禁用宏执行。境内货源地取模板“达县”，产地保留模板空值；品牌完整取合同申报要素，ITEM# 取 PL Customer Item No.；交仓日期、备注、车牌留空，发票号填合同号。
- 星辉仓逐行区分普通箱货和板货：普通装箱说明未包含打板信息时，板数和每板箱数留空；包含卡板、托盘等信息时按每板箱数计算，缺失、冲突或不能整除时停止提示。包装说明为空时提示核实，不直接当作箱货。任意一行有板货，整单“是否有板货”填“是”，全部为箱货则填“否”。989 样本仍为 10/4 板、每板 180/120 箱。长宽高和体积均取 PL 箱数据，体积单位 CTN。计价数量按发票单位，法定数量按查询单位，分别填写，不混用。
- 三个仓库共用程序目录的 `hs_units_cache.json`：先按商品编码读取成功记录，命中后直接使用，重启后仍有效，不设自动过期时间。未命中才在后台查询 `https://www.hsbianma.com/search?keywords=<10位商品编码>`，只读取编码精确匹配行的“计量单位”，`/` 前后分别为法1、法2。JSON 保存每次联网的编码、时间、网址、单位或失败原因，`entries` 为可复用的成功记录，`queries` 为联网历史。缺文件时首次查询后自动创建，打包运行时保存在 EXE 旁；删除某编码的 `entries` 记录即可下次重新查询。损坏缓存会提示并重新联网，重建前备份损坏文件；写入失败会提醒，但本次查询结果仍可使用。
- 未缓存编码查询超时、网络错误、无匹配、冲突或无法识别单位时，会弹窗显示商品编码、装箱单数量和失败原因，等待选择“重试查询”“手动确认并继续”或“取消生成”。失败结果不会阻止下次重查；重试仅查询失败编码。手动确认须明确选择法1、法2（或无第二法定单位），继续执行数量核对，仅本次有效，不写入网站成功缓存，来源记入每日日志。关闭弹窗等同取消，取消不输出文件。
- 每次生成先一次性读取本地缓存并检查全部编码，再仅联网查询缺失或无效项；全部命中时不访问网络。界面显示本地命中数、待联网数，查询结束后切换为核对数据、Excel 保存提示，避免把保存耗时误认为网络等待。
- 装箱单总数量支持“1920套 23040个”：通过单价和金额唯一确定计价数量并核对发票单位，保留所有单位数量。法定单位为“个”时取 23040；同一商品拆成多条 PL 时按每行计价数量比例分配，并核对法定数量合计，不能精确分配或件数非整数时停止。总数量只有数字时，该数字直接作为法1总数量；千克数量取对应 PL 行净重。无第二法定单位则相关两列留空。有单位标注却缺少目标单位数量时，提示补齐换算依据。查询网址、单位及逐行数量来源写入每日详细日志。
- 商品按完整中文品名（或三单品名最后一个 `/` 后的完整名称）与单价唯一匹配；多合同或商品不能唯一对应时弹窗选择。生成前重新读取源文件，核对逐行数量×单价、装箱数量，以及与三单对应的数量、箱数、金额和净毛重汇总。发票单位缺失/冲突、数据不一致则停止并显示问题。申报价值保留 Excel 计算公式；输出结果及详细原因写入当天日志。
- “选择海关装箱单”读取 `.xlsx` 的 PL 明细（适配 `asn/PL-11369    309件.xlsx`），按原表顺序逐行显示客户、PO、客户订单、货号、中英文品名、数量、每箱数量、箱数、长宽高、单箱及总净毛重、CBM、品牌、包装、单价、材质、出货日期、SO 等字段。页面保留逐行数据，每行也写入当天日志。此操作独立于三单核对，可直接选文件读取。
- 海关明细显示为“表头一行 + 每条数据一行”，字段用 ` | ` 分隔，支持横向滚动。单元格内的换行显示为空格、原有 `|` 显示为全角 `｜`，原始数据仍保留在模型和详细日志中。
- 海关装箱单的 SO、客户、订单号等文本列若纵向合并，按实际合并区域为覆盖的每条明细读取首格值，日志和三个仓库 ASN 均使用该值。普通空格不向下沿用，数量、重量等数字列不复制合并值，避免重复计数；源文件保持不变。
- 海关装箱单每条货物明细独立保存在 `customs_data.rows`，记录工作表、原行号、读取值及原始值，为后续一行对应一行生成 ASN 使用；不合并相同货号或相同 SO。合计、空行、表头、底部备注不计入明细。样本读取 12 行、309 箱、1,236 件；缺字段或公式缓存缺失会提示，保留问题行。成功后记住文件路径，重新打开需选择文件读取；读取新文件失败时清除旧明细。
- 应用右下角 `− / +` 调整所有页面和应用内弹窗的字体，范围 10–24；`settings.json` 的 `ui_font_size` 保存基础字号，重启自动恢复。原有设置字段保留。

## 自动工厂箱单生成

“自动工厂箱单生成”tab 中，选择订单 PDF 目录、订单分类排期表、JP 产品资料表和输出目录，勾选订单后点击“生成合并工厂箱单”。订单目录搜索子目录中的 PDF，不再需要客户订单表目录。选择成功后记住路径，重启时自动加载所选资料表；本页的选择与原有装箱功能独立。

- 选择订单目录后，将找到的全部 PDF（含子目录）列入带复选框的表格，默认不勾选。文件名过滤支持连续片段，如 `167`、`759`；仅匹配文件名，不匹配父目录。筛选只隐藏不匹配的行，保留勾选；“全选 / 全不选”作用于当前显示的文件，清空过滤后可操作全部文件。界面显示总数、显示数、勾选数及隐藏行的勾选数。
- 仅勾选的订单合并为一个 Excel，每个非零数量 item 一行；未勾选不读取、不参与计算。生成时锁定本次选择，不自动加入目录里新出现的文件；没有勾选时不可生成，切换目录或重启后重新勾选，已勾选文件被删除时停止并提示。默认输出到 `output/factory_packing_lists/总箱数.xlsx`，也可另选输出目录。保存后自动用本机 Excel 打开，同名文件不覆盖。
- 使用 `templates/factory_notice.xlsx`（来自 `FACTORY_NOTICE_SAMPLE.xlsx`）的标题、列顺序与格式；清除示例内容，按实际明细数扩展，末尾汇总件数、箱数、净重、毛重、总体积和卡板数。
- 箱数为 PDF QTY / Packing 每箱数量；净重、毛重严格读取 JP 表的“整箱净重kg / 整箱毛重kg”。多条资料记录时弹窗选择，订单 Packaging 高亮显示。JP 样例中产品名称前的无表头货号列也可读取。
- 包装方式按采购订单号＋item 匹配排期表。优先完整订单号和完整 item；排期只有无批次订单号时使用生产订单号，无 item 列时可使用工作表货号。不同包装要求弹窗选择，不借用其他订单的记录。
- 单行 CBM 为 `箱数×长×宽×高/1000000`，NW/GW 为箱数乘单箱重量；箱数、重量、体积及合计均保留 Excel 公式，打开 Excel 后自动重算。
- Packaging 包含 SLIP SHEET 时，从原始 REMARKS 中按货号提取每托箱数，卡板数为箱数除以每托箱数；缺失、冲突或不能整除时停止本次合并，提示核对。
- SO 列保留并留空，生成后用户在 Excel 中补填；不再读取客户订单表 PDF 或匹配 Shipper booking number，旧配置中的客户订单表目录自动忽略。底部订仓号、柜号、车牌等填写栏继续留空，按需手动填写。
- Customer 优先从订单 PDF 的 CUSTOMER NAME 后第一行客户名称读取，兼容同一行文本形式；没有该标签时，读取 Ultimate Consignee 首行，按位置排除相邻栏位及地址。两者同时存在时优先 CUSTOMER NAME；无法读取或同一字段出现冲突名称时提示具体 PDF 文件名。Customer Item No. 从订单读取；英文描述取 DESCRIPTION 第一行，中文取 JP 产品名称，品牌取英文描述首词。单价、表面材质和出货日期留空。
- 打开生成文件时从 A1 显示，保留可见的 A 列 Customer。只冻结前三行表头，不冻结列，移除 E/F 之间贯穿工作表的冻结竖线。合计下方自动添加黄底、红色加粗的装货箭头温馨提示；右侧提供订仓号、柜号、封条号、出口方式、出口国家、出货期、运输、车牌八项空白填写栏，随明细数量调整位置并纳入打印区域。
- 遇到损坏订单、重复采购订单、缺少关键资料或取消选择时不输出本次合并箱单，防止生成缺行或重复计数的结果。

验证命令：`python -m unittest discover -s tests -v`。`tests/test_factory_packing.py` 包含本地样例集成验证，`tests/test_factory_ui.py` 在 Windows 下验证路径保存与重新加载。

## 启动

Windows 打包版位于 `dist/LoveAnna.exe`，双击运行，无需安装 Python 或 pip 依赖。打包配置包含界面资源、五个 Excel 模板、ASN 写入脚本及 PDF/Excel 处理库。

仅在明确要求时重新打包。2026-09-26 已更新 EXE，包含三个仓库 ASN、工厂订单 PDF 勾选过滤、两种客户名称标签兼容和本地海关单位缓存；不含 OCR。后续源码改动不会自动更新已有 EXE，源码运行使用下方命令。

`settings.json`（路径、字号）和 `packing_rules.json`（装箱推荐容差）独立放在 EXE 同目录；缺失时启动自动创建，已有配置保留。日志和默认输出也使用 EXE 同目录，不写入单文件程序的临时解包目录。业务输入文件仍由界面选择。ASN 的原生 `.xls` 保存及自动打开 Excel 功能需要本机 Microsoft Excel，Office 不包含在 EXE 内。

手动打包：安装 `requirement.txt` 和 `requirement-build.txt`，运行 `python -m PyInstaller --noconfirm LoveAnna.spec`。可运行 `LoveAnna.exe --self-test <报告JSON绝对路径>` 验证实际打包环境中的界面、配置、模板、PDF 读写、三个仓库的原生 Excel 生成及星辉仓宏保留；验证生成的临时工作簿会自动清理。

在项目目录、用于运行程序的 Python 环境执行：

```powershell
python -m pip install -r requirement.txt
python main.py
```

依赖统一维护在 `requirement.txt`，ASN 的 `.xls` 读取使用 `xlrd`。不再安装图片识别引擎和模型。

## 输入资料

四组控件在同一行：订单 PDF 目录、JP 产品资料表、订单排期表、输出目录。

- PDF 目录递归扫描子目录，界面显示文件名与数量；处理时从 PDF 正文读取 Purchase Order No.，不依赖文件名。
- 首次切换到“自动装箱生成”时优先查找 `main.py` 同目录的 `JP产品净重毛重外箱尺寸表*.xlsx` 和 `*订单分类排期汇*总*.xlsx`；没有本地文件时尝试 `settings.json` 中保存的路径。
- 文件加载成功才保存路径。每次启动或手动选文件都会后台预读取。产品资料按 ITEM NO 建立索引，订单排期保留所有工作表的原始行列。

订单 PDF 需包含可读取的文字。订单号和客户 PO 保留文本前导零。

## 生成装箱单

点击“直接处理所有pdf订单”，使用所选目录中的订单 PDF、JP 产品资料和订单排期，逐个订单生成 `订单号.xlsx`，保存到所选输出目录（默认 `output/packing_lists`）。

每个装箱单保存成功后立即请求本机 Microsoft Excel 打开，随后继续处理后续订单。已存在而跳过的文件不重复打开。Office 打开失败只记录日志，不影响已保存文件和后续生成；无需新增 Python 依赖。

- 每个订单在读取 PDF 前检查目标文件；已存在则记录日志并跳过，继续处理下一订单。保存采用排他创建，不覆盖旧文件。完成时分别统计成功、已存在跳过和失败数量。
- 每个订单要求唯一 PDF。读取完整主 ITEM，不把 ASSORTMENT 子款当作额外订单行，支持本地示例的跨页明细。
- 排期先匹配完整订单号，无完整号时使用去掉末尾批次号的生产订单号；结合完整 ITEM 或工作表货号查找“产品日期码”。缺失或冲突时不生成该订单。
- 产品资料优先匹配完整 ITEM，再匹配短货号，支持资料单元格内多个货号。多条匹配会弹窗显示行号、装箱数量、尺寸、净重、毛重和备注，由用户选择。不同订单分别确认。
- CASE PACK / QTY 使用 PDF，箱数为 QTY / CASE PACK，不能整除时停止该订单。资料表装箱数量与 PDF 不同会写日志，尺寸重量按所选记录读取。
- BOX 为长×宽×高 / 1000000（CM → CBM）。总体积按范例保留三位小数，合计为各行求和。重量按箱数相乘。结果直接写数值，无需打开 Excel 计算即可读取。
- 玩具种类使用订单 PDF 的 DESCRIPTION 第一行，剔除同一行末尾的数量、单位和价格，不再翻译产品资料表名称。选择弹窗中只读显示该内容。Battery Included 按需求填 N。
- 模板 `templates/packing_list.xlsx` 来自用户提供的范例，已去除截图。行数根据 ITEM 数调整。DATE 使用生成当天日期；Expected Delivery Date 从排期表对应订单、ITEM 的“询单要求交期”读取，写为 Excel 日期并显示 `yyyy-mm-dd`。支持 Excel 日期、日期序列值和明确年月日文本；缺失或冲突则记录日志并跳过订单。若不同 ITEM 交期不同，在顶部列出各个日期。多个 DATE CODE 在顶部按货号列明，ITEM 单元格批注记录日期码与资料来源。
- 任一 ITEM 缺失关键资料时跳过整张订单，不生成缺行文件；其他订单继续处理，日志汇总结果。
